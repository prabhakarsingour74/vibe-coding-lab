## 🏗️ How the hybrid setup works

```text
Your computer
    |
    +-- Project A  -----------------> GitHub: project-a (PUBLIC)
    |
    +-- Project B  -----------------> GitHub: project-b (PRIVATE)
    |
    +-- Project C  -----------------> GitHub: project-c (PUBLIC)
                                           |
                                           v
                              vibe-coding-lab (PUBLIC INDEX)
                              Public links + descriptions only
```

Each project is an independent repository. This master repository is a curated index, not a parent repository or a place to put private project code.

## 🚦 Project lifecycle

1. **Capture** — write the concept using the [idea template](_templates/IDEA_TEMPLATE.md).
2. **Build** — create a separate local project folder and Git repository.
3. **Choose visibility** — create its GitHub repository as private or public.
4. **Develop** — keep source code, issues, dependencies, and releases in that project repository.
5. **Publish** — when a project is public and ready, add it to the relevant category index here.
6. **Maintain** — update the listing when its description, status, or demo changes.

See [WORKFLOW.md](WORKFLOW.md) for practical commands.

## 🔐 Privacy and security

- Never push private project source code, secrets, customer data, or confidential notes into this public repository.
- Do not add private repository URLs, names, or descriptions unless you intentionally want that information public.
- A private project stays private in its own repository; changing this index does not change project visibility.
- Before making a private repository public, review its Git history, branches, tags, releases, issues, wiki, Actions logs, and files for sensitive information.
- Never commit `.env` files, API keys, access tokens, or credentials.
